# ひな形の下書き（TPL_BRIEF）

ガバナンス道場の「ひな形」を下書きする。ひな形は、利用者が自社用に書き換えて使う骨子・審査票・質問票・手順。
道場の約束は「嘘の無いように」。**各行は、検証済みの1行（索引）を根拠に指すか、「判断」と明記する。**

## 渡すもの
- 索引：`cite_index.tsv`（1行1件。`ポインタ<TAB>本文（日本語）`）。作り方は `scripts/cite_index.py`。
- 1件の全文（英語・出典名）を見るとき：`python3 .claude/skills/govdojo-maintenance/scripts/cite_index.py --resolve '<ポインタ>'`
- 索引は grep で引く（例：`grep -n '漏えい' cite_index.tsv`）。全部を読み込まない。

## 作る4つ
| id | 名前 | 中身 |
|---|---|---|
| policy | AI利用規程の骨子 | 規程の章立てと、各章に書く条項の要点（目的・適用範囲、体制と責任、利用の区分と承認、入力してよい情報、出力の扱い、外部サービスの利用、台帳と棚卸し、教育、事故時、見直し など） |
| review | ユースケース審査票 | 1件のAI利用を審査するときの確認項目（基本情報、影響を受ける人、判断への影響、扱うデータ、顧客向けか、自律実行と権限、評価の計画、市場・法域、判定と条件） |
| vendor | ベンダー・モデル審査の質問票 | 外部のAIサービス・モデルの提供者に聞く質問（入力の学習利用、保存と保持、再委託、セキュリティ、評価・レッドチーム、学習データと著作権、生成物の表示、監査とログ、規約改定、障害・事故の連絡、エージェントの権限 など） |
| incident | インシデント初動の手順 | AIが関わる事故の最初の動き（受付、停止・遮断、影響範囲、報告義務の要否、証拠、説明、再開の条件、再発防止と台帳の更新） |

各ひな形は**14〜22行**。節（sections）に分け、1節2〜5行。

## 行の書き方
- `t`：[日本語, 英語]。ひな形の1項目として短く（日本語はおおむね60字以内）。審査票・質問票は問いの形（〜か／〜はどうなっているか）、骨子・手順は「〜を定める」「〜する」の形。
- `cite`：根拠のポインタの配列（1〜3件）。**行に書く事実（期限・数字・対象・義務か任意か・法域）は、指した行に書いてあることだけ**。
- `judge`：根拠の行から直接は言えない実務上の勧め（例：「年1回見直す」）は `judge: true` にし、`cite` は空にする。迷ったら判断にする。
- 外国の規定に拠る行は、行の中で法域を示す（「EU向けに提供する場合」「コロラド州の消費者に重大な決定をする場合」など）。
- 「期待する」「望ましい」「should」を「義務」「must」と書かない。指した行が任意・指針なら、行も義務として書かない。
- 判断の行は全体の3割以下を目安にする。
- 簡体字・キリル文字を入れない（中国の機関・制度の正式名称を除く）。

## 出力
JSON を指定のパスに書く。**早めに書き出し、節ができるたびに上書きする**（コンテナの再起動で消えるため）。

```json
{"list":[
  {"id":"policy","name":["AI利用規程の骨子","AI use policy outline"],
   "purpose":["…何に使うか（1文）","…"],
   "sections":[
     {"h":["目的と適用範囲","Purpose and scope"],
      "lines":[{"t":["…","…"],"cite":["reg:jp-ai-biz-guideline:who:0"],"judge":false}]}
   ]}
]}
```

終わったら、各ひな形の行数・判断の行数・使ったポインタの数を報告する。
