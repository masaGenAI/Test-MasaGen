# 業界シナリオ（ガバナンス道場）― 作成の指示

道場の「シナリオ」に、業界の規定を踏まえた判断の練習を足す。金融・医療・公共・製造で各2本、計8本。
**根拠は検算済みの材料だけ**：ind_final.json（業界別の規定）、regs_final.json（規制マップ）、k_kit/kit_final.json（実務キット）、lc/lc_final.json（ローコード統制）。
材料にない事実（日付・数字・規定の中身）を入れない。規定がAIに直接触れていない場合は、選択肢・解説でも「当てはめ」として扱う。

## 1本の形（既存のシナリオと同じ。JSON 配列で quiz/scen_new.json に書く）
```json
{"id": "sc-fin-xxxx", "title": "短い題（25字以内）", "industry": "金融|保険|医療|公共|製造", "tier": "high|limited|minimal|prohibited",
 "setup": "状況（あなたの立場を含む。120〜220字）",
 "steps": [
   {"q": "問い", "qEn": "English",
    "choices": [{"t": "選択肢", "tEn": "...", "ok": false, "fb": "なぜ違うか／正しいか（60〜140字）", "fbEn": "..."}, ... 3つ、正解は1つ],
    "principle": "この段で学ぶ原則（40字以内）", "principleEn": "..."},
   ... 3段
 ],
 "ref": ["ind:fin:0", "kit:inv:fields", ...]}
```
- 各シナリオ3段。段は時系列（導入の相談 → 統制の設計 → 運用中の問題 など）。
- 正解の位置は段ごとに散らす。正解の選択肢がいつも一番長くならないようにする（長い錯乱肢も混ぜる）。
- 例：金融「生成AIでの融資稟議書の下書き（FISC・委託管理・個人情報）」「AIの与信スコアの説明（モデルリスク・米国の不利益通知の考え方）」、医療「病院での生成AI利用（3省2ガイドラインの生成AI Q&A）」「AI搭載のプログラム医療機器の再学習（変更計画の手続）」、公共「自治体の生成AIチャットの調達（デジタル庁のガイドライン・ISMAP）」「住民の個人情報を扱う生成AI（行政機関等の規律）」、製造「設計図面を海外のAIサービスで扱う（営業秘密・輸出管理）」「工場の設備にAIをつなぐ（工場システムのセキュリティガイドライン・製造物責任）」。題材は材料で裏づく範囲で選び直してよい。
- 煽り語なし。実在の企業名を悪く書かない（架空の組織にする）。
- `ref` は検算用（差し込むときに外す）。
