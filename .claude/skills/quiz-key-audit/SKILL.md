# 正解の番号のブラインド検品

## なぜやるか

問題の多くは AI が作っている。これまでの点検でも、正解の番号が1つずれている問題が繰り返し見つかった
（2026-10 の2回の点検で計66問）。誤った正解で覚えると、解かないより悪い。
解説の文面から機械的に拾う方法（`key-scan.mjs`）は、解説が正解の選択肢の語句を含むときしか効かない。
このスキルは、**正解を見ていない解答役に全問を解かせ、答えが食い違った問題だけを人（または上位のモデル）が読む**。
読む量は全体の数％で済む。

## 役割の分け方（費用を抑える）

| 役 | 何をする | 向いている担い手 |
|---|---|---|
| 準備・突き合わせ | 書き出し・集計・台帳 | スクリプト（`prep.py`・`compare.py`） |
| 解答役 | 正解を伏せた問題を解く（1ファイル50問） | 小さいモデルのサブエージェント（複数を並行） |
| 判定役 | 食い違った問題だけを読み、正解の番号が誤りかを決める | まとめ役（上位のモデル）。必要なら出典に当たる |

解答役が見るのは問題文と選択肢だけ。全バンクで約3.8万問・問題文と選択肢で約700万字ある（2026-11 時点）ので、
**一度に全部回さない**。台帳が確認済みの問題を覚えているので、ハブ・バンクごとに分けて進め、次からは増えた分・直した分だけ回す。

## 手順

リポジトリのルートで行う。`W` は作業フォルダ（例：`/tmp/keyaudit`）。

1. **書き出す**
   ```bash
   python3 -I .claude/skills/quiz-key-audit/scripts/prep.py W --mod CertHubModule          # ハブを絞る
   python3 -I .claude/skills/quiz-key-audit/scripts/prep.py W --bank GOVDOJO_BANK          # バンクを絞る
   python3 -I .claude/skills/quiz-key-audit/scripts/prep.py W --sample 200 --seed 1        # まず標本で食い違いの率を見る
   ```
   `W/in/chunk-0001.json …` ができる。同じ文面の問題は1問にまとめ、台帳で確認済みの問題は除く（`--recheck` で入れる）。
   **写しどうしで正解の番号が食い違う問題**（`W/clash.json`）は、解くまでもなくどちらかが誤りなので、先に読んで直す。

2. **解かせる**：`references/solver-brief.md` を渡して、解答役にファイルを1つずつ割り当てる（`W` と番号を伝える）。
   答えは `W/out/chunk-XXXX.json` に書かせる。解答役には原稿・`key.json`・`scan/` を見せない。

3. **突き合わせる**
   ```bash
   python3 -I .claude/skills/quiz-key-audit/scripts/compare.py W            # 答えの不備・未回答があれば止まる
   python3 -I .claude/skills/quiz-key-audit/scripts/compare.py W --partial  # 返った分だけで集計
   ```
   `W/report.md` に、バンクごとの食い違いの数と、食い違った問題（選択肢・正解とされている番号・解答役の答え・解説）が出る。

4. **判定する**：食い違った問題を1問ずつ読み、`W/decisions.json` に書く。
   ```json
   [ { "id": "0001-07", "verdict": "key-wrong", "note": "解説は B の内容。正解の番号が A になっている" } ]
   ```
   - `key-wrong`：正解の番号が誤り → 直す
   - `ambiguous`：正解が2つある・問題文が曖昧・事実が古い → 問題を直す
   - `key-ok`：正解の番号は合っている（解答役の誤り）
   食い違いの多くは解答役の誤りなので、**食い違い＝誤り、として機械的に直さない**。解説と選択肢を読み、
   事実に関わるものは出典で確かめる。

5. **直す・記録する**：`key-wrong`・`ambiguous` は quiz-authoring の決まりで直す（直したら `npm run validate`）。そのうえで
   ```bash
   python3 -I .claude/skills/quiz-key-audit/scripts/compare.py W --record
   ```
   一致した問題と `key-ok` の問題が台帳（`data/quiz-key-audit/ledger.json`）に入る。直した問題は文面が変わるので台帳に入らず、
   次に回したときにもう一度解かれる。

## 読み方の目安

- 食い違いの率は、バンクの質の目安になる。率が高いバンクは、正解の番号だけでなく問題の作りも疑う。
- 解答役が `issue` を書いた問題（`report.md` の末尾）は、一致していても読む価値がある（事実が古い・正解が2つ、の申告）。
- 解答役の確信度が `high` なのに食い違った問題から読む。`low` の食い違いは、難しいだけのことが多い。
- 解答役と正解の番号が**両方とも**誤っている問題は、この方法では見つからない。全問一致は「誤りが無い」の証明ではない。

## 原稿の置き場（2026-11 から）

`nova-app/src/ProjectNova.jsx` は、git に入っている部品（`nova-app/src/parts/`）をつないだ作業用の写し。
`prep.py` は最初に写しと部品をそろえる。`report.md` の場所は、部品のファイルと行で出る。
