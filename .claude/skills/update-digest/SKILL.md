# 更新一覧（何が・どこに・反映済みか）

コミット履歴から「画面のどこが変わったか」を人に伝わる形でまとめる。
`nova-app/src/ProjectNova.jsx` は全ハブが入った 1 ファイル（約 23 万行・100MB）なので、ファイル名だけでは場所が分からない。
差分の行番号とファイル内の目印からハブ・タブ・資格を割り出すスクリプトを使う。

## 1. 期間を決めて道具を回す

```bash
# 既定は今日から 7 日。期間を指定するなら --since/--until（両端の日を含む）
python3 .claude/skills/update-digest/scripts/changes.py --days 7 --pages
python3 .claude/skills/update-digest/scripts/changes.py --since 2026-10-29 --until 2026-11-05 --pages --json out.json
```

- 初回は 1 コミットあたり数秒かかる（ProjectNova.jsx の差分が重い）。結果は `.git/update-digest-cache.json` に残るので 2 回目からは速い。
  時間がかかるときはバックグラウンドで回す。
- `--pages` は `gh api` で GitHub Pages に公開中のコミットを調べる。取れなければ「未確認」と出る。
- `--min-lines N` で、ProjectNova.jsx を N 行未満しか触っていない場所を省ける（共通の小修正が多い期間向け）。
- 出力は「場所ごと」と「コミットごと」の 2 部。場所はポータルのハブ順、TechHub はタブ順に並ぶ。

## 2. 一覧を書く

出力をそのまま貼らない。場所ごとに、何が変わったかを日本語で短くまとめ直す。

- **見出しは場所**：「TechHub › セキュリティ・ガバナンス道場」「Certification Hub › PL-900」のように、利用者が画面で辿る名前で書く。
- **中身は変化**：同じ場所の複数コミットは 1〜3 行にまとめる（例：「規制マップ・業界別チェックを追加し、7業種＋5業種と問題 216 問を追加」）。
- **数はコミット件名か差分から取る**。件名にない数を書くときは `git show <hash> --stat` や差分で数え直す。推測で数を書かない。
- **英語の件名は意味で訳す**。迷ったら `git show <hash>` で中身を見る。
- **反映状況を必ず書く**：`--pages` の「公開中のコミット」がブランチ最新と同じなら「公開済み」。違えば、どのコミットまで公開されたかを書く。
  公開ページそのものを開いて確かめられない環境（github.io への接続が拒否される等）では、そのことも書く。
- **アプリに出ない変更は最後に別枠**：作業用スキル、CLAUDE.md・docs、ビルドの仕組み（読み込みの分割など）。
  ただしビルドの変更でも「表示が速くなった」など利用者に見える効果があるなら、その効果を該当の場所に書く。
- 1 つのコミットが多くの場所にまたがる（コントラスト修正・英語表示・名称変更など）ときは、
  横断の変更として 1 行にまとめ、「どのハブ／資格に及んだか」を列挙する。

## 3. 判定の限界（そのまま書かない）

- **TechHub のタブは推定**。差分の見出し（git が付ける直前の関数・定数名）を、今の版の参照関係（`tab === "id" && <Comp` から辿る）でタブに直している。
  共通部品は「複数タブ」「タブ未特定」と出るので、件名や差分を見て書き分ける。
- **ハブの判定は目印頼み**。`const XxxModule = (function`・`const Station_Xxx =`・`// Project-Nova : Portal Shell` の直前の目印で決める。
  目印より前（ファイル冒頭）は「全ハブ共通の部品」になる。
- **「【未分類のファイル】」が出たら** `references/places.json` の `paths` に対応を足す。新しいハブを足したら `modules` にも足す。
  資格の表示名を直したいときは `stations` に足す（既定は `PL900` → `PL-900` のように自動で区切る）。
- **行数は量の目安にならない**。問題バンクは 1 バンク＝1 行の長い配列で入っていることが多く、113 問を足しても「+4/−4行」と出る。
  問題数・件数はコミット件名か、差分の中身を数えて書く。
- コミットの日時は記録された日時（タイムゾーンはコミットのもの）。「1週間」は日付で区切る。
- アプリを変えないコミット（スキル・文書だけ）は Pages のデプロイが走らない。公開中のコミットが「アプリを変えた最後のコミット」と同じなら公開済みと判断してよい。

## 4. 出力の形（例）

```
## ここ1週間（10/29〜11/5）の更新 — 123 コミット、公開済み（ea928eb）

### TechHub › セキュリティ・ガバナンス道場
- 規制マップ・業界別チェックを新設し、12業種と問題 316 問を追加（10/30〜10/31）
- …

### Certification Hub › PL-900
- 2026年7月の出題範囲に作り直し、245 問を追加（11/1）

### アプリに出ない変更
- 作業用スキル：govdojo-maintenance を追加（10/31）
```

## 5. アーティファクトにする

「アーティファクトにして」「ページにして」と頼まれたとき、または一覧を人に渡すときに行う。
2 章でまとめ直した一覧を JSON に書き、決まった見た目のページにして公開する。
見た目（ポータルのハブ色、左に日付・右に変更の台帳、ダークテーマとスマホ幅に対応）は `references/page-style.css` にあり、毎回デザインし直さない。

1. **一覧を JSON に書く**。形は `references/summary-example.json`（10/30〜11/5 の週の実例）に合わせる。
   作業ファイルはリポジトリに入れず、作業用フォルダ（scratchpad）に置く。
   - `sections`：画面の場所ごと。`color` はハブ色のキー（`portal`・`megatech`・`cert`・`finance`・`consulting`・`ling`・`lang`・`book`・`liberal`・`side`・`training`・`tracker`・`off`）。
     `short` は上の移動バーに出す短い名前、`badge` は「新設」などの印。
   - `groups`：タブや資格ごとの小見出し（`heading`）と項目（`items`）。
   - `items`：`when`（日付）と、自分で書いた文 `html`（`<strong>`・`<ul><li>`・`<span class="n">` を使ってよい）。
     外から取ってきた文をそのまま入れるときは `text`（エスケープされる）。
   - 期間が長い一覧（1か月など）では、直近の項目に `"recent": true` を付け、`recent_label`（例「直近1週間（10/29〜）だけ表示」）を入れる。
     絞り込みのチェックボックスが出る。
   - 日別のコミット数の棒グラフ：`"days": "auto"` にして `--changes` に `changes.py --json` の出力を渡す。手で書くなら `[["10/30", 4], …]`。実測した数だけを書く。
   - `pages`：`state` は `published`（公開済み）・`partial`（途中のコミットまで公開）・`unknown`（未確認）。
     `note` に、どう確かめたか（GitHub 側のデプロイ記録か、公開ページを開いたか）を書く。
2. **ページを作る**：
   ```bash
   python3 .claude/skills/update-digest/scripts/make_page.py summary.json page.html --changes changes.json
   ```
3. **公開前に 1 回だけ見る**（スクリーンショットか、Artifact のプレビュー）。横のはみ出しや文字の欠けがあれば直し、見直しは繰り返さない。
4. **Artifact ツールで公開する**。
   - 新しいアーティファクトを作るときは、ツールの決まりどおり最初に `action: "quickstart"`（`intent: "other"`）を呼ぶ。型（Dashboard など）は使わず、普通のページとして公開する。
   - `file_path` は作った HTML、`icon` は `"list"`（初回だけ）、`description` は期間と中身を言う一文。ページの名前は JSON の `title`（例「Project Nova 週間更新」「Project Nova 更新一覧」）。
   - 同じ一覧を直すときは同じファイルパスで公開し直す（URL が変わらない）。期間の違う一覧は別のファイル・別の名前にして、別のアーティファクトにする。
5. **報告する**：URL、載せた中身（期間・コミット数・公開状況）、非公開であること（ほかの人に見せるにはページの共有メニューから共有が要る）、元の HTML の場所。
