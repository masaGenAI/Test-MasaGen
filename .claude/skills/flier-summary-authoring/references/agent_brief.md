# flier 書籍要約の作成（担当分）

作業フォルダ `WORK` と担当 id は、依頼文に書いてある。

## 読むもの
- `WORK/plan.json`: 担当 id の行（`pdf` の stem、`mode` が replace か new、`category`）。
- `WORK/img/<stem>_pN.png`: PDF の全ページ画像。**Read ツールで全ページを見て本文を読む**。縦書き・段組みなので、右の列から左へ、上の段から下の段へ読む。
- `WORK/txt/<stem>.txt`: 抽出テキスト。列の順が崩れているので本文としては使わず、数字の照合にだけ使う。
- `mode` が replace の本は、今の記録（`/home/user/Test-MasaGen/nova-app/public/booksummaryhub.html` の `{"id":"<id>"`）を表記の参考にする。今の記録の内容が PDF にないものは使わない。
- 手本: 同じファイルの `{"id":"comp02"`（形と密度。読むだけ）。

## 書くもの
`WORK/out/<id>.json`（UTF-8、正しい JSON）:
```json
{"id":"<id>",
 "oneLiner":"本書の核心を1文で（60〜110字）",
 "overview":"著者の立場、本書の問い、構成と流れ、結論（350〜500字）",
 "points":[{"h":"見出し（8〜20字）","b":"本文（120〜230字）"}],
 "takeaway":"実務への示唆（180〜300字）"}
```
- points は 6〜9 個。PDF の小見出しの順に沿う。合計（overview＋points本文＋takeaway）は 1,500〜1,900字。
- `mode` が new の本は、PDF の1ページ目から `"title"`, `"author"`, `"publisher"`, `"year"`（刊行年4桁）, `"pages"`（数字のみ）を、定価があれば `"price"`（例 "1,500円"）も入れる。訳書は author を「著者名（訳者名訳）」の形にする。

## 守ること
1. PDF 本文に書かれていることだけを書く。一般知識での補足・推測・自分の評価を足さない。数値・固有名詞・書名・人名は PDF にあるものだけ。読み取りに自信がない数字・固有名詞は書かない。
2. 冒頭の「要約者レビュー」「おすすめポイント」は flier の要約者の文章。著者の主張と混ぜない。使うなら overview で「要約者は〜と紹介する」と書き分ける。
3. 本書の主張は「本書は〜と説く」「著者は〜とする」と分かる書き方にする。本書が引用する他の本・人物の説は出典を明記する。
4. PDF の文を長く書き写さない。自分の言葉で要約する（短い用語・キーフレーズの引用は可）。
5. takeaway は本書の提案を読み手の実務に落とした示唆。本書が言っていない施策を「本書は勧める」と書かない。本の範囲を超える一般論を足さない。
6. 常体。簡体字（cp932 で表せない漢字）・キリル文字・全角ダッシュ「—」を使わない。
7. 担当の `WORK/out/<id>.json` 以外、リポジトリには書き込まない。作業用ファイルは `WORK/tmp_<担当名>/` の中だけ。
